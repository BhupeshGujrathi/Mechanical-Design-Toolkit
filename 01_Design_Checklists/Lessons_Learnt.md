# 📚 Engineering Lessons Learned Library

> **Failures are an inevitable part of product development. Repeating the same failures is optional.**

> Every prototype failure, tooling issue, assembly problem, field complaint, or supplier deviation is an opportunity to improve future designs.

> The purpose of this library is to convert engineering experience into reusable knowledge.

---

# Why Maintain a Lessons Learned Library?

During every product development project, teams generate valuable knowledge through:

- Prototype failures
- Tool trial observations
- Manufacturing issues
- Assembly challenges
- Supplier feedback
- Customer complaints
- DFMEA actions
- CAPA investigations

**Unfortunately...**

Once the project is complete, this knowledge is often forgotten.

The next project starts from scratch and unknowingly repeats the same mistakes.

A Lessons Learned Library prevents that cycle.

# Every Lesson Should Answer Five Questions

## 1️⃣ What failed?

Describe the issue clearly.

Example:

- Injection Molding Defects?
- Quality & Relaibility Requirements?
- Performance?
- Safety Issues?

---

## 2️⃣ Why did it fail?

Document the verified root cause.

Avoid assumptions.

Use:

- 5 Why
- Fishbone Diagram
- Fault Tree Analysis
- DOE
- Mold Flow Analysis
- Simulation

---

## 3️⃣ How was it corrected?

Record the corrective action.

Example:

- Design Update
- Process Update
- Testing Criteria Update
- Measurement Techniques Update
  
---

## 4️⃣ How can it be prevented?

This becomes the design guideline.

Example:

Effective use of 

- DFM&A guidelines
- DFMEA & PFMEA Techniques
- Understanding manufactring process capability & limitations 

---

## 5️⃣ Can this knowledge help another project?

Every lesson should be reusable.

Tag it with:

- Design Isuue (DFM, DFA, DFX)
- Tooling Issue
- Process Isuue
- Packaging Issue
- Verfication Issue
- Validation Issue

---

# Build an Engineering Idea Bank

Every failure eventually leads to one or more improved solutions.

Don't only document the failure.

Capture the new idea that solved it.

Example

| Failure | Improved Idea |
|----------|---------------|
| Sink Marks | Core out thick sections |
| Warpage | Balanced wall thickness |
| Screw Failure | Snap-fit design |
| Long Assembly Time | Integrated locating features |
| Excessive Cost | Single molded component |

Over time this becomes an **Engineering Idea Bank**.

Instead of asking:

> "How do we solve this?"

Engineers can first ask:

> "Have we solved something similar before?"
